# Сервисная архитектура

Статус: реализовано (актуально)
Дата: 2026-08-31

## Принципы

1. Все сервисы — контейнеры Docker, оркестрация через Docker Compose.
2. API доверяет claims JWT и не содержит собственной аутентификации.
3. Реальное подключение сервиса пользователей не должно требовать переработки бизнес-логики.

## Статус реализации

- Работают (compose): `proxy`, `web`, `api`, `admin`, `mock-auth`, `db`, `tiles` (Martin, MVT).
- Запланировано: `geo` (Dadata, фаза 6).
- RBAC (фаза 3) и редактирование объектов на карте (фаза 4.1) реализованы.

## Схема взаимодействия

```
                     ┌──────────────────────────────────────────────┐
                     │                     proxy                   │
                     │         (reverse proxy, единый вход)         │
                     └───────┬──────────────┬──────────────┬───────┘
                             │              │              │
                    /api     │       /tiles │              │ /mock-auth
                             │              │              │
                     ┌───────▼─────┐  ┌─────▼──────┐  ┌────▼──────────┐
                     │     api     │  │   tiles    │  │  mock-auth    │
                     │   (NestJS)  │  │  (Martin)  │  │  (JWT issuer) │
                     └───────┬─────┘  └─────┬──────┘  └───────────────┘
                             │              │
                             │   SQL        │   SQL
                             └───────┬──────┘
                                     │
                              ┌──────▼──────┐
                              │     db      │
                              │   PostGIS   │
                              └─────────────┘

        web (Vue 3 + MapLibre) ──► proxy  (браузер инженера)
        admin (Vue 3 + Naive UI) ─► proxy  (браузер администратора)
```

Поток запросов от браузера идёт через `proxy`. `mock-auth` отдаёт JWT, `api` и `tiles` потребляют данные из `db`. `tiles` отдаёт векторные тайлы напрямую браузеру (MapLibre).

## Описание сервисов

### 1. `web` — SPA сетевого инженера
- **Стек:** Vue 3 + Vite + MapLibre GL JS.
- **Задачи:**
  - отрисовка карты и объектов по слоям (слои строятся из справочника);
  - вкл/выкл отображения слоёв (по правам пользователя);
  - создание/редактирование/удаление объектов на карте (geoman, фаза 4.1);
  - CRUD-интерфейсы для объектов (generic по типам из справочника);
  - работа с JWT: логин через `mock-auth`, хранение токена, передача в запросах.
- **Зависимости:** api (CRUD), tiles (карта), mock-auth (вход).

### 2. `admin` — SPA администратора (справочники)
- **Стек:** Vue 3 + Vite + TypeScript + Naive UI.
- **Задачи:**
  - ведение справочников: типы объектов, слои, типы связей (CRUD);
  - редактор `attrs_schema` (JSON Schema) типов объектов — пока JSON-textarea в форме, структурный редактор (4.3) в плане;
  - работа с JWT: логин через `mock-auth`, доступ по праву `object-types:manage`.
- **Маршрут через proxy:** `/admin/`.
- **Зависимости:** api (CRUD), mock-auth (вход).

### 3. `api` — бизнес-логика и RBAC
- **Стек:** Node.js + NestJS (REST, OpenAPI).
- **Задачи:**
  - generic-CRUD объектов по типам из справочника (один набор эндпоинтов);
  - CRUD справочников (типы объектов, слои, типы связей) — для админ-интерфейса;
  - валидация атрибутов по `attrs_schema` (JSON Schema, ajv);
  - CRUD связей объектов (фаза 4.4, ещё не реализован);
  - разграничение доступа: видимость и редактирование по динамическим permissions из claims JWT (`ObjectPermissionGuard`, `PermissionsGuard`, реализовано).
- **Зависимости:** db (хранение), mock-auth (валидация подписи JWT).

### 4. `tiles` — сервер векторных тайлов
- **Стек:** Martin v1.14.0 (самосбор из исходников; PostGIS-источники, MVT).
- **Задачи:**
  - генерация векторных тайлов (MVT) из PostGIS для MapLibre (SQL-функция `tiles_objects(z,x,y,query_params json)`);
  - отдаёт слои для отображения.
- **Авторизация:** Martin не имеет встроенной auth → nginx `auth_request /internal/tile-auth` (→ `/api/me`, валидирует JWT) → из заголовка `X-Object-Types` подставляются права в `?types=...`; без JWT 401.
- **Зависимости:** db.

### 5. `db` — хранилище геоданных
- **Стек:** PostgreSQL + PostGIS.
- **Задачи:**
  - справочно-ориентированная модель: `layers`, `object_types`, `objects`, `relation_types`, `object_relations` (см. docs/03-objects);
  - поддержка тайлов (MVT) и пространственных запросов;
  - seed первичного набора типов.
- **Зависимости:** нет (фундамент).

### 6. `mock-auth` — заглушка аутентификации
- **Стек:** лёгкий (Node.js Express или готовый компонент).
- **Задачи:**
  - `POST /mock-auth/login` — возвращает подписанный JWT по логину/имени тестового пользователя;
  - поддерживает набор предопределённых пользователей с разными permissions;
  - общий секрет подписи с `api` (проверка подписи).
- **Зависимости:** нет.

### 7. `proxy` — обратный прокси
- **Стек:** Nginx (лёгкий) или Traefik.
- **Задачи:**
  - единая точка входа, маршрутизация по путям (/api, /tiles, /mock-auth, /admin/ — статика admin, / — статика web);
  - (позже) TLS/HTTPS.

## Модель JWT (claims)

| Claim           | Назначение                                       |
|-----------------|--------------------------------------------------|
| `sub`           | идентификатор пользователя (login)               |
| `name`          | отображаемое имя                                 |
| `role`          | роль (например `engineer`, `admin`, `viewer`)     |
| `permissions`   | права, например `["objects:pole:read", "objects:pole:write", ...]` |

Формат permissions финализирован: docs/04-access/access-model.md.

## Что ещё обсуждаем (открытые вопросы)
