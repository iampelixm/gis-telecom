# Модель доступа

Статус: черновик (обсуждается)
Дата: 2026-08-30

## Принципы

1. Аутентификацию выполняет внешний сервис пользователей. Сейчас — заглушка `mock-auth`, выдающая JWT.
2. `api` доверяет claims JWT и строит разрешения только на их основе.
3. Права динамические, привязаны к кодам типов из справочника (`docs/03-objects/object-catalog.md`). Новый тип = новые права без изменения кода.

## Формат permissions в JWT

Права — список строк в claim `permissions`.

### На объекты (типы из `object_types`)

```
objects:<code>:read      — видеть объекты типа
objects:<code>:write     — создавать/изменять/удалять объекты типа
```

### На связи (типы из `relation_types`)

```
object-relations:<code>:read   — видеть связи
object-relations:<code>:write  — изменять связи
```

### На справочники

```
object-types:manage      — CRUD типов объектов, слоёв, типов связей (админ)
```

### Примеры

- Инженер, работающий с оптикой:
  `["objects:pole:read", "objects:pole:write", "objects:fiber_line:read", "objects:fiber_line:write", "objects:splice:read", "objects:splice:write"]`
- Наблюдатель (только просмотр):
  `["objects:pole:read", "objects:fiber_line:read", ...]`

## Роли (упрощённые, для mock-auth)

| Роль | Описание | Базовые permissions |
|------|----------|---------------------|
| `admin` | полный доступ + управление справочниками | `*` + `object-types:manage` |
| `engineer` | чтение и запись по назначенным типам | набор `objects:<code>:read|write` |
| `viewer` | только чтение по назначенным типам | набор `objects:<code>:read` |

Роль задаёт базовый набор, но решающим считается точный список `permissions` в токене.

## Действие прав по слоям

- Видимость слоя на карте = наличие `objects:<code>:read` хотя бы у одного типа этого слоя.
- Переключатель видимости: скрытые по правам слои не показываются в переключателе.
- Редактирование объекта = наличие `objects:<code>:write`.
- Кнопки создания/редактирования скрываются на фронте, запрет дублируется на `api` (сервер — источник истины).

## Вопрос на доработку

- Нужно ли разграничение по территории (инженер видит только свой район)? Если да — добавим claim `area_ids` и проверку по региону в запросах.
